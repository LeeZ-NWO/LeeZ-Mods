# Core mod idea

The goal is to make **fuel a valuable and strategically limited commodity**.

At the moment, fuel in 7 Days to Die can be accumulated too easily.

This mod should fundamentally change the fuel economy.

Players should need to plan fuel collection, transport, storage and resupply.

---

# Portable fuel containers

Fuel should primarily be carried in **tiered gas cans / jerry cans**.

These containers should have limited storage capacities.

Initial reference idea:

* approximately **500 fuel units** for an early/basic can

The final tier count and capacities are not decided yet.

Possible future design:

* T1 small/basic gas can
* T2 medium can
* T3 larger can
* higher tiers with progressively greater storage

Do not lock tier capacities until we have inspected the existing game balance.

The preferred long-term design is a reusable fuel container that can hold a variable amount of fuel, rather than simply increasing normal gasoline stack size.

---

# Refuelling design

Vehicles, generators and fuel-powered tools should eventually require fuel to be supplied from an appropriate portable gas can/container.

The player should need to carry fuel with them when operating vehicles or fuel-powered equipment away from base.

We need to investigate the existing V3.1 refuelling systems before deciding how to implement this.

Do not assume XML alone will be sufficient.

Harmony/runtime code may be necessary.

---

# Remove easy fuel production

The intended design is:

* **No crafting gasoline from oil shale.**
* Remove/disable other easy fuel production paths where appropriate.
* Players should not be able to harvest ordinary objects simply to create large quantities of usable gasoline.
* Fuel should mostly enter the economy through finite world fuel repositories.

We must first audit all current fuel creation/recovery sources before removing anything.

---

# World fuel repositories

Gasoline should primarily be obtained from physical world locations.

Primary source:

* Gas station pumps

Other possible sources:

* fuel barrels
* drums
* service-station tanks
* large fuel storage tanks
* industrial tanks
* other appropriate tank-style props already present in the game

We need to identify every suitable V3.1 block, prefab or world prop before deciding which become functional fuel repositories.

Each repository should have **finite fuel stock**.

Initial reference value:

* approximately **200 fuel units per working pump/tank**

This value is provisional and will need balancing.

---

# Repository restocking

Fuel repositories should replenish periodically.

The intended concept is for fuel restocking to occur at roughly the same frequency as the **supply-drop aeroplane/event**.

We need to inspect V3.1 and determine:

* exact supply-drop scheduling
* server settings affecting supply drops
* whether there is an event/hook we can reuse
* whether fuel should literally restock when the supply-drop event fires
* or simply use the same interval

This must work correctly in multiplayer and survive save/reload.

---

# Persistence

Each fuel repository may need to remember:

* current fuel quantity
* maximum capacity
* last refill/restock time
* whether it has already been drained during the current restock cycle
* destroyed/depleted state if applicable

This state must survive:

* save/reload
* chunk unload/reload
* server restart

Multiplayer synchronization must be considered from the beginning.

# Design philosophy

The purpose of this mod is not simply to make gasoline annoying.

Fuel should become another strategic survival resource.

The intended gameplay should encourage:

* planning routes
* locating gas stations
* maintaining reserve fuel
* deciding whether a trip is worth the gasoline
* carrying emergency fuel
* defending useful fuel locations
* planning long journeys
* using higher-tier containers as meaningful progression
* periodically returning to known fuel repositories after restock

Fuel scarcity should create decisions rather than busywork.
